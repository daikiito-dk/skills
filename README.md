# Skills

Reusable AI development skills for building real software projects.

## Philosophy

These skills are designed around a simple idea:

> Build good software first. Let GitHub activity and achievements emerge naturally from good development.

The repository focuses on practical workflows that connect product quality, engineering quality, and healthy GitHub development practices.

## Available Skills

### GitHub Development Health Check

`skills/github-development-health-check/SKILL.md`

Audit a GitHub repository and determine:

- product quality
- engineering quality
- GitHub workflow quality
- collaboration readiness
- portfolio value
- repository maturity
- natural GitHub achievement opportunities
- the three highest-value next actions

It can also continue from an audit into an autonomous development loop when explicitly requested.

### Invocation

```text
check <repository>
```

Examples:

```text
check daikiito-dk/Ghost-Protocol
check daikiito-dk/trustyon
check https://github.com/owner/repository
```

Useful modes:

```text
check repo
check github
check engineering
check portfolio
check achievement
check release
```

## Development Loop

The preferred workflow is:

```text
Idea
  ↓
Issue
  ↓
Branch
  ↓
Implementation
  ↓
Test
  ↓
PR
  ↓
CI
  ↓
Review
  ↓
Fix
  ↓
Merge
  ↓
Release
  ↓
Documentation
```

The workflow is a guide, not a reason to create artificial activity.

## Achievement Policy

GitHub achievements are treated as a byproduct of meaningful development.

Do not create:

- meaningless issues
- trivial commits
- artificial pull requests
- fake reviews
- unnecessary discussions
- releases without product value

The goal is a healthy public development history, not activity farming.
